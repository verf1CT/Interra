# Инструкция по защите и экранированию сервера биллинга stat.interra.ru

Данный рунбук предназначен для системных администраторов «Интерры» и руководства. 

**Цель:** за 10 минут ликвидировать критическую уязвимость публичного доступа к старому Apache 2.2 и ядру 2017 года без остановки биллинга NetUP UTM5 и без прерывания обслуживания абонентов.

---

## 1. В чём проблема сейчас (Текущее состояние)
* Сервер `stat.interra.ru` «смотрит» в публичный интернет старым веб-сервером **Apache 2.2.22** (сборка 2012 г.) на ядре **Linux 3.2** (Ubuntu 12.04 LTS, EOL апрель 2017 г.).
* Сервер открыто сообщает свою версию в заголовках (`Server: Apache/2.2.22 (Ubuntu)`), привлекая автоматические сканеры уязвимостей.
* Присутствует уязвимость перед локальным повышением привилегий (LPE) и эксплойтами для устаревшего сетевого стека.

---

## 2. Архитектура решения (Экранирование / Reverse Proxy)

Вместо сложной и рискованной единовременной переустановки биллинга применяется проверенная телеком-практика **экранирования**:

```
[Абонент / Мобильное приложение]
               │ (HTTPS : 443 / TLS 1.3 + WAF + Rate Limit)
               ▼
┌──────────────────────────────────────────────┐
│  Nginx (Современный внешний щит)              │
│  - Закрывает прямой доступ к Apache          │
│  - Скрывает все версии ПО (server_tokens off)│
│  - Принудительный HSTS и защита от DoS       │
└──────────────────────┬───────────────────────┘
                       │ (HTTP : 8080 только на 127.0.0.1)
                       ▼
┌──────────────────────────────────────────────┐
│  Apache 2.2 (NetUP UTM5 CGI / aaainfo)        │
│  - Слушает ТОЛЬКО localhost (127.0.0.1)       │
│  - Из интернета напрямую недоступен          │
└──────────────────────────────────────────────┘
```

---

## 3. Пошаговый план внедрения (10 минут)

Все готовые конфигурационные файлы подготовлены в репозитории в папке [`deploy/stat.interra.ru/`](../deploy/stat.interra.ru/).

### Шаг 1. Подключение к серверу
```bash
ssh root@stat.interra.ru
```

### Шаг 2. Скачивание готовых конфигов
```bash
cd /root
git clone https://github.com/verf1CT/Interra.git interra-repo || (cd interra-repo && git pull)
cd interra-repo/deploy/stat.interra.ru
```

### Шаг 3. Запуск автоматического скрипта изоляции
```bash
sudo bash hardening.sh
```

Скрипт автоматически:
1. Создаст полную резервную копию `/etc/apache2/` в `/root/backup_apache_...`.
2. Установит Nginx и Certbot (если ещё не установлены).
3. Переведет Apache на внутренний порт `127.0.0.1:8080` (в файле `/etc/apache2/ports.conf`).
4. Установит защищённый конфиг `nginx-stat.interra.ru.conf` с современным шифрованием TLS 1.2/1.3, защитными заголовками и защитой от перебора паролей.
5. Проверит синтаксис конфигов и мягко перезагрузит сервисы без разрыва сессий.

---

## 4. Проверка результата

Выполните команду проверки заголовков снаружи (со своего компьютера или смартфона):
```bash
curl -I https://stat.interra.ru/
```

**Ожидаемый результат:**
```http
HTTP/2 200
server: webserver
strict-transport-security: max-age=31536000; includeSubDomains
x-content-type-options: nosniff
x-frame-options: SAMEORIGIN
x-xss-protection: 1; mode=block
```
* Сигнатура `Apache/2.2.22 (Ubuntu)` полностью исчезла.
* Прямое подключение к порту Apache снаружи блокируется.
* Биллинг и мобильное приложение продолжают работать в штатном режиме, но теперь сервер защищён.
