# Приложение ЛК Интерра

Flutter-приложение для iOS и Android. Показывает баланс, тариф, услуги и историю платежей из биллинга UTM5, умеет открыть оплату, проверить сеть и показать устройства в домашнем Wi-Fi. Версия лежит в `pubspec.yaml` (сейчас 1.0.2+29), Flutter 3.44, Dart от 3.3.

Цвета фирменные: синий `#3A96D6` и оранжевый `#F77D31`, шрифт Manrope, есть светлая и тёмная темы.

## Откуда берутся данные

У UTM5 нет JSON API, поэтому всё идёт через два канала.

**Вход через `bbb`.** Это штатный CGI биллинга `stat.interra.ru/cgi-bin/utm5/bbb`. Регистрация одноразовая:

1. `cmd=set&app=<15 случайных цифр>` - биллинг отдаёт 24-значный токен приложения.
2. `cmd=get&num=<телефон>&app=<токен>` - на телефон приходит SMS с кодом.
3. `cmd=set&num=<код>&app=<токен>` - подтверждение, приложение записано в базу.
4. `cmd=open&app=<токен>` - при каждом открытии отдаёт свежую ссылку на кабинет вида `?login=...`, она живёт около 30 минут.

Токен и телефон лежат в `flutter_secure_storage`. Коды ответа `0` и `1` разбираются как "регистрация потеряна" и "телефон отвязан", пользователь видит понятный текст.

**Страницы кабинета как HTML.** По ссылке из `open` приложение скачивает `aaainfo...&oper=info`, `oper=tariffs`, `oper=reports` и разбирает их пакетом `html` в `services/cabinet_parser.dart`. Парсеры (`parseCabinetHtml`, `parsePaymentsHtml`, `parseServicesHtml`) - чистые функции от строки, под них есть тесты на сохранённых страницах. Если провайдер поменяет вёрстку кабинета, пропадут баланс и тариф, поэтому это самое хрупкое место проекта.

Ответ Apache приходит без `charset`, так что тело декодируется вручную как UTF-8 (`decodeResponseBody`).

Когда на номере несколько договоров, кабинет сначала отдаёт страницу выбора. Приложение берёт первый договор, а выбранный запоминает в `CabinetParser.activeLogin`: по этой ссылке потом ходят тарифы, услуги и история. Номер для оплаты у договора виден только на его странице, в ссылке лежит внутренний логин.

Наш сервер в этих потоках не участвует. С ним приложение говорит только про push: один раз регистрирует FCM-токен и категории уведомлений на `push.interra.ru`.

## Экраны

`CabinetScreen` - контейнер с нижней навигацией: Главная, Услуги, ТВ, История. Он грузит данные, держит выбор договора и раздаёт данные по вкладкам. Главная сама догружает услуги и платежи для плиток абонплаты и последнего пополнения, при ошибке плитки просто не показываются.

| Файл | Что делает |
|------|-----------|
| `register_screen.dart` | вход: телефон, SMS-код, пауза между отправками 60 секунд |
| `cabinet_screen.dart` | контейнер вкладок, выбор договора |
| `home_tab.dart` | баланс, тариф, абонплата, последнее пополнение |
| `services_screen.dart` | услуги и тарифы |
| `premium_tv_screen.dart` | ТВ: пакеты каналов |
| `payments_history_screen.dart` | операции по месяцам |
| `settings_screen.dart` | тема, уведомления, замок, выход |
| `support_screen.dart` | звонок, чат, ВКонтакте, помощь |
| `diagnostics_screen.dart` | проверка по шагам: интернет, DNS, сайт, биллинг |
| `biometric_gate.dart`, `pin_setup_screen.dart` | замок приложения: биометрия и код |

## Сервисы

| Файл | Назначение |
|------|-----------|
| `billing_api.dart` | запросы к `bbb` |
| `cabinet_parser.dart` | скачивание и разбор страниц кабинета |
| `secure_http.dart` | HTTP с закреплёнными корнями сертификатов (GlobalSign R3, ISRG X1 и X2 из `assets/certs`), только для наших хостов |
| `auth_store.dart` | токен и телефон в защищённом хранилище |
| `balance_store.dart` | кэш баланса, форматирование (`1 250,50 ₽`), передача в виджеты и на часы |
| `page_cache.dart` | снимок кабинета на случай офлайна, чистится при выходе |
| `push_service.dart`, `notify_prefs.dart`, `api_client.dart` | FCM, категории уведомлений, регистрация устройства на сервере |
| `biometric.dart`, `pin_lock.dart` | Face ID или отпечаток, код-пароль (SHA-256 с солью, пауза после 5 ошибок) |
| `net_diagnostics.dart` | проверки сети: интернет, DNS, сайт, биллинг |
| `quick_actions_service.dart` | ярлыки по долгому нажатию на иконку |
| `update_check.dart` | сверяет версию с `pubspec.yaml` в ветке main, пока приложения нет в сторах |
| `demo_mode.dart` | вымышленный абонент для скриншотов магазинов и модераторов |
| `analytics.dart`, `app_info.dart` | Firebase Analytics и Crashlytics, версия из нативного пакета |

Расчёты над данными биллинга (абонплата, на сколько хватит баланса, группировка по месяцам) лежат в `utils/billing_math.dart`.

## Дизайн-система

Палитра и тема - `theme.dart`: поверхности и текст берутся через `context.p`, бренд-цвета через `AppColors`. Общие виджеты - `widgets/design_system.dart`, `ui_kit.dart`, `motion_kit.dart` (пружины, бегущие цифры, блик по карточке). Подтверждения и выбор из списка - нижние шторки из `widgets/app_sheets.dart`, а не диалоги. Обе темы нужно проверять при каждой правке.

Каждый экран с данными поддерживает демо-режим: при добавлении нового экрана нужны обе ветки, боевая и демо.

На главном экране показываем только то, что реально отдал биллинг, без придуманных метрик.

## Безопасность

- замок приложения: биометрия и код, настраиваемая задержка перед повторным запросом
- закрытие экрана в переключателе задач (`PrivacyShield`)
- закрепление корневых сертификатов для запросов к своим хостам

Если у Интерры сменится удостоверяющий центр, корень нужно добавить в `assets/certs` и в `_pinnedRoots`, иначе приложение перестанет ходить в биллинг.

## Нативная часть

iOS (`ios/`): Runner с мостом к часам и фоновым обновлением, `BalanceIntents.swift` для Siri, виджеты `BalanceWidget`, приложение `InterraWatch` для Apple Watch, `NotificationService` для расширенных уведомлений, общий `Shared/BalanceCore.swift`.

Android (`android/`): `BalanceWidgetProvider` (виджет на домашнем экране), `BalanceTileService` (плитка быстрых настроек), `MainActivity`.

Баланс, номер счёта и токен приложение кладёт в общее хранилище (iOS - App Group `group.ru.interra.lkInterra`, Android - `HomeWidgetPreferences`), оттуда их читают виджеты, плитка, Siri и часы.

## Разработка

```bash
flutter pub get
flutter analyze lib test
flutter test
flutter run
```

Тесты лежат в `test/`: парсер кабинета, переключение договоров, расчёты биллинга, баланс, ответы `bbb`, телефон, форматтеры, блокировка, проверка версии, демо-режим.

`flutter analyze` на Windows падает, если в пути к проекту есть кириллица (`FormatException`). Обход: `subst I: "<путь к репозиторию>"` и запуск из `I:\app`. `flutter test` кириллицу переносит нормально.

Скриншоты экранов в демо-режиме для ревью дизайна:

```bash
SHOTS_DIR=<папка> flutter test tool/shots.dart
```

## Сборка

```bash
flutter build apk --release
flutter build appbundle --release
flutter build ios --release --no-codesign
```

Подписанные APK и AAB и неподписанный IPA собирает CI (`.github/workflows/ci.yml`). Для Android локально нужны `android/key.properties` и keystore, без них сборка подписывается debug-ключом. Оба файла в git не попадают. IPA ставится через Sideloadly или AltStore. Push на iOS включается отдельно, см. [`../docs/IOS_PUSH_SETUP.md`](../docs/IOS_PUSH_SETUP.md).

Что нужно для публикации в магазины: [`../docs/STORE_CHECKLIST.md`](../docs/STORE_CHECKLIST.md) и [`../docs/APP_STORE_READINESS.md`](../docs/APP_STORE_READINESS.md).
